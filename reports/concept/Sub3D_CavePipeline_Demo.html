Sub3D — Pipeline F : génération de caves intéressantes

Démo pédagogique du pipeline §4.4 de Sub3D_WorldDesign_Reference.md. Chaque étape produit un output passé à la suivante. Les visualisations sont 2D pour la lisibilité — l'implé UE5 sera 3D mais la logique reste identique. Bouton Régénérer rejoue avec un nouveau seed.

Stage 1 — Topology Graph

graph theory + spatial embedding

Vue top-down (plan X-Z). À gauche : une lecture inspirée du proto mesh actuel (grosses cavités organiques + rétrécissements). À droite : la même intention structurée en graph. Le graph est la colonne vertébrale du système. Deux couches superposées :

  • G_sub — trunk clairsemé, chambers + outposts, tunnels sub-navigables. Peu d'edges par node, distances longues.
  • G_PCE — passages cavités étroites (non-navigables sub). Réseau dense, intriqué, avec ses propres loops + joinings. Bridges ponctuels vers chambers.

Le joueur cartographie d'abord G_sub (route principale), puis G_PCE par EVA (exploration intriquée).

Proto mesh : F = smin(capsules/sphères à radius variable) + bruit organique G = G_sub ∪ G_PCE ∪ E_bridge G_sub : chambers/outposts + trunk clair, radius large G_PCE : nodes pondérés par conductance C(x), edges courts + cycles contrôlés C(x) : soft rock + faults + shell chambers - protected authored masks
(a) Proto mesh inspiré — masses organiques, blobs, passages fins. Même logique SDF/smooth-min que le proto actuel, mais dessinée en 2D.
(b) Graphe cible — G_sub lisible + G_PCE intriqué. La topologie devient contrôlable avant la réalisation mesh.
 Outpost (authored fixed)  Chamber (procédural G_sub)  PCE node (procédural G_PCE)  Trunk sub-navigable (G_sub)  Passage PCE (réseau étroit)  Squeeze (sous-set des PCE)  Bridge PCE → chamber

Observe : le proto mesh à gauche garde ce que tu apprécies : forme organique, aléatoire, cavités larges, filaments étroits. Le graph à droite explique ce qui manque au proto seul : un réseau PCE dense interconnecté, avec rejoins, raccourcis, loops et bridges vers chambers. Les PCE ne sont pas des dead-ends : ils forment leur propre carte EVA.

Stage 2 — Geological Substrate

voronoi + stratification + faults + FBM

Vue cross-section verticale (X-Y, 500 m × 300 m). Le champ scalaire S(x, y, z) ∈ [0, 1] représente la dureté de la roche. Composé pondéré de 4 termes superposés. Encode 3 ères géologiques (Q-6ter validé).

S(x, y, z) = w₁ · S_strat(y) // stratification horizontale + w₂ · S_voronoi(x, y, z) // blocs tectoniques + w₃ · S_faults({fault_i}, x,y,z) // 3 ères de fault planes + w₄ · FBM(x, y, z, octaves=4) // rugosité multi-scale
Cross-section verticale. Bleu sombre = roche tendre. Bleu clair = roche dure. Lignes rosées = fault planes (3 ères).

Observe : 3 groupes de fault planes à orientations différentes (3 ères). Les Voronoi blocks créent des "blocs tectoniques" avec boundaries nettes. La stratification donne le gradient vertical. La superposition produit une story embedded (C6) : on lit que des faults récentes coupent à travers d'anciennes.

Stage 3 — Geometric Realization

SDF + manifold dual contouring

Le SDF combine le skeleton du graph (Stage 1) et la modulation par le substrate (Stage 2). La forme finale n'est plus un cylindre lisse autour du tunnel : elle suit les fault planes, s'élargit dans le soft sediment, se rétrécit dans la hard rock.

F(x, y, z) = max( -F_tunnel(x, y, z; G, tag) , // carving (negative inside tunnels) S(x, y, z) - threshold ) // substrate hardness surface = { (x, y, z) : F(x, y, z) = 0 } extraction = Manifold Dual Contouring (Schaefer 2007)
(a) Sans substrate — tunnel comme un cylindre lisse. Géométriquement vide. Pas de plausibilité géologique.
(b) Avec substrate — parois suivent les boundaries Voronoi et fault planes. Variation de diamètre. C'est la même topologie mais habillée géologiquement.

Lecture clé : c'est l'interaction Stage 1 ⊕ Stage 2 qui produit l'intérêt visuel. Aucune des deux étapes seule ne suffit. C'est pourquoi un algo single-pass échoue.

Stage 4 — Detail decorator pass

poisson + curvature + wetness/heat

Une fois le mesh extrait, on scatter les détails micro : stalactites/stalagmites par curvature-driven placement, sédiment au fond par gravity-driven, bioluminescence dans les zones humides, accretion minérale près des hydrothermal. Implémentation native via PCG Framework UE 5.7 — pas besoin de coder ça à la main.

Surface carved de Stage 3 + decorators. ▲ stalactites au top concave • sédiment au bottom plat • ★ biolum dans les zones humides.

Stage 4 est indépendant de Stages 1-2-3 — il consomme la surface finale + des champs (curvature, wetness, heat) calculés au runtime. C'est ce qui rend possible l'itération sans rebake du mesh.

Composition complète — Canyon vertical avec cavités (biome scène #1)

pipeline complet — Q-9 validé

Application du pipeline complet à un setup "canyon vertical" — biome retenu pour la première scène de référence (Q-9). Vue side view, 400 m × 600 m. Le spine descend verticalement. Les cavités branchent latéralement à différentes profondeurs. Substrate avec 3 ères géologiques. Decorators biolum sporadiques.

400 m large × 600 m profond. Cross-section verticale. L'aspect 3D sera donné par la rotation autour de l'axe vertical en UE5.

Lecture cartographique : un seul spine vertical clair, plusieurs cavités latérales mémorables, réseau PCE depuis les chambers. Le joueur peut construire un mental map : "descendre, à droite niveau ~200m la grande cavité, puis réseau étroit qui rejoint plus bas par deux passages".

Heuristiques §4.8 visibles ici : variance dimensionnelle des cavités, branching factor 2-3 par node, loops si présents (rares en vertical pur), vertical drops naturels (le spine est un drop), EVA labyrinthes superposés au sub-highway central.
